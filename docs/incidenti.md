# Управљање инцидентима

Сервис периодично прегледа најновије догађаје и отвара инцидент за категорије `SecurityAlert` и `SafetyInterlock`.

Статуси:

- `Open` (0) — нов инцидент
- `Acknowledged` (1) — инцидент је потврђен
- `Resolved` (2) — инцидент је затворен

Статус може напредовати, али не и враћати се уназад.

Читање: `GET /api/incidents` са кључем за преглед.

Промена статуса: `POST /api/incidents/{id}/status` са администраторским кључем и телом `{"status":1,"actor":"admin"}`.

Када је активан PostgreSQL, инциденти и њихов тренутни статус трајно се чувају у табели `incidents`. При меморијском складишту губе се након рестартовања. За већ постојећу базу потребно је ручно применити допуну из `deploy/postgres/init.sql`; Docker иницијализација се извршава само над празним volume-ом. Детаљна историја сваке промене статуса још није посебно моделирана, али се измене бележе у audit догађајима. Сервис обрађује ограничен број последњих догађаја; при великом оптерећењу потребна је поуздана редна обрада.
