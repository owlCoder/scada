# IEC 60870-5-104 server (grid mode)

The API process can host an IEC 60870-5-104 slave (controlled station) that exposes the grid RTUs of the active
`GridDefinition` the way a real SCADA master talks to substations: a master connects over TCP, sends `STARTDT`, runs a
general interrogation and then receives spontaneous data whenever the grid steps, and issues select-before-operate
commands for switches and tap changers. Implementation: [src/Protocols/Iec104](../src/Protocols/Iec104). The server is
disabled by default and binds IPv4 loopback; it is independent of the water-plant Modbus/OPC UA servers.

Enable for a local run:

```bash
Protocols__Iec104__Enabled=true dotnet run --project src/Api -- --urls http://127.0.0.1:5080
```

In Docker use `deploy/compose.iec104.yaml` (publishes `127.0.0.1:2404` only and sets
`Protocols__Iec104__BindAddress=0.0.0.0` inside the container) together with `SCADA_IEC104_ENABLED=true`.

## Settings (`Protocols:Iec104`)

| Setting | Default | Purpose |
| --- | --- | --- |
| `Enabled` | `false` | Starts the listener with the API host. |
| `BindAddress` | `127.0.0.1` | IPv4 bind address. |
| `Port` | `2404` | TCP port, 1024-65535. |
| `MaxConnections` | `4` | Concurrent master connections, 1-64. |
| `K` | `12` | Max unacknowledged sent I-frames before waiting for an S-frame. |
| `W` | `8` | Received I-frames after which an S-frame acknowledgement is sent (W ≤ K). |
| `T0` | `30` | Seconds to wait for `STARTDT` after connect; then the connection is closed. |
| `T1` | `15` | Acknowledgement timeout for sent I-frames and `TESTFR act`; expiry closes the connection. |
| `T2` | `10` | Max delay before acknowledging received I-frames with an S-frame. |
| `T3` | `20` | Idle supervision; on expiry the slave sends `TESTFR act`. |
| `AllowedClients` | empty | Allowed client IPv4 addresses; empty means loopback only. |
| `CommandsEnabled` | `true` | When false, command ASDUs get a negative activation confirmation. |
| `CommandActor` | `iec104-master` | Actor name attributed to every command (the protocol cannot authenticate clients). |
| `CommandRole` | `Operator` | Role attributed to commands; must be Operator or Administrator. |

## Link layer (APCI/APDU)

- APDU: start byte `0x68`, one length octet (4-253, counting APCI + ASDU), 4-octet control field, ASDU payload.
- I-frames carry data with 15-bit send/receive sequence numbers that wrap at 32767 (`V(S)`/`V(R)`).
- S-frames acknowledge received I-frames (`RECV` sequence in the control field); sent after `W` received I-frames or on t2.
- U-frames: `STARTDT act/con` (0x07/0x0B), `STOPDT act/con` (0x13/0x23), `TESTFR act/con` (0x43/0x83).
- k/w flow control: after `K` unacknowledged I-frames the slave stops sending data frames until the master acknowledges;
  t1 expiry (no acknowledgement) closes the connection; t3 sends `TESTFR act` when the link is idle; t0 closes
  connections that never send `STARTDT`.
- **No data is sent before `STARTDT act`**; an I-frame before `STARTDT` closes the connection. Malformed frames (bad
  start byte, length, control field or ASDU) are audited and close the connection; the server loop never throws.
- Each connection has a bounded outbound queue; a slow client that cannot keep up is closed (audited), never allowed to
  block the simulation or other clients.

## ASDU layer

Common address (CA) = RTU `CommonAddress`; information object addresses (IOA) are 3-byte little-endian; originator
address is echoed. Supported type identifications:

| Type | Name | Direction | Data |
| --- | --- | --- | --- |
| 1 | M_SP_NA_1 | slave→master | SIQ (1 octet) |
| 3 | M_DP_NA_1 | slave→master | DIQ (1 octet; 1=open, 2=closed) |
| 5 | M_ST_NA_1 | slave→master | VSI step position (1 octet) |
| 13 | M_ME_NC_1 | slave→master | short float + QDS (5 octets) |
| 30 | M_SP_TB_1 | slave→master | SIQ + CP56Time2a (8 octets) |
| 31 | M_DP_TB_1 | slave→master | DIQ + CP56Time2a |
| 32 | M_ST_TB_1 | slave→master | VSI + CP56Time2a |
| 36 | M_ME_TF_1 | slave→master | short float + QDP + CP56Time2a (12 octets) |
| 46 | C_DC_NA_1 | master→slave | DCO (select/execute bit 7, state bits 0-1: 1=open, 2=close) |
| 47 | C_RC_NA_1 | master→slave | RCC (bits 0-1: 1=raise, 2=lower) |
| 59 | C_DC_TA_1 | master→slave | DCO + CP56Time2a |
| 100 | C_IC_NA_1 | master→slave | QOI (20 = general interrogation) |
| 103 | C_CS_NA_1 | master→slave | CP56Time2a |

Causes of transmission used: 3 spontaneous, 6 activation request, 7 activation confirm (positive), 8 negative
activation confirm, 10 activation termination, 20 interrogation response, and 44/46/47 for unknown type / common
address / information object address. CP56Time2a is the 7-octet time tag (ms, minutes, hours, day, month, day of week,
year). Measurement quality bytes use the IEC 60870-5 layout (bit 4 blocked, 5 substituted, 6 not topical, 7 invalid);
`MeasurementQuality` maps Good→0, Uncertain→substituted, Bad→invalid|not-topical. Both the general interrogation and the
spontaneous monitor evaluate every point on `GridViewRedactor.ForOperators` of the current snapshot: the slave only ever
reports the **operator view** — reported measurement values and reported switch/tap states — never true values, spoofing
state or injected faults.

Behaviour:

- **General interrogation** `C_IC_NA_1` (QOI 20) per CA: act con (COT 7), all points of that CA as data (COT 20), act term (COT 10).
- **Clock sync** `C_CS_NA_1`: acknowledged with act con (COT 7); the server clock is never changed.
- **Spontaneous data**: on every grid step (`IGridObserver`) changed points are sent with COT 3 and CP56Time2a time
  tags. Measurements use a deadband of 0.5 % of the point range (bus nominal kV, line rated A / derived MVA, transformer
  rated MVA, load peak MW, generator rated MW, capacitor rated Mvar); discrete points (switch, tap, trip, RTU status)
  are sent on any change. The first observed step only primes the baseline.
- **Double command** `C_DC_NA_1`/`C_DC_TA_1` with S/E bit: select open/close → `SelectOpen`/`SelectClose`, execute →
  `Execute`, deactivation (state 0, execute) → `Cancel` on `IGridControl` with actor `CommandActor`/`CommandRole` and
  source `iec104`. Answer: act con (COT 7 positive / 8 negative per `GridCommandResult`, 47 for unknown IOA) and act term (COT 10).
- **Regulating step** `C_RC_NA_1`: 1 → `TapRaise`, 2 → `TapLower` on the addressed transformer; same confirm/term flow.
- Unknown type → COT 44, unknown CA → COT 46, unknown IOA → COT 47 (negative confirmation, no act term).
- Commands are only accepted when `CommandsEnabled=true` and the client is allowed; every command, connection
  open/close/rejection and malformed frame is audited through `IEventPublisher` (category `Protocol` / `CommandRejected`).

## Address map

Deterministic from `IGridView.Definition`, per RTU (`Iec104AddressMap`): elements listed in the RTU's `ElementIds` are
mapped in definition order into IOA ranges **1000+ measurements, 2000+ switch status (double points), 3000+ tap
positions, 4000+ protection trip (single points), 5000+ RTU status** (1 = online, 0 = active communication-loss alarm).
Element→points: bus→voltage; line→current/active/reactive power; transformer→current/active/reactive power plus tap
position when it has an OLTC; switch→double point status; load/generator→active/reactive power; capacitor→reactive
power; protection→trip single point. Commands reuse the status IOA: a switch command addresses the switch's double
point IOA, a tap command the tap IOA. Unknown element ids are skipped.

The map is published for documentation at `GET /api/grid/iec104/map` (Viewer role; 404 while the protocol is disabled).

## Security notes

IEC 60870-5-104 has no authentication or encryption: anyone who can reach the port can interrogate data and, when
`CommandsEnabled=true`, operate switches and taps. Therefore: keep `BindAddress` on loopback (default) or restrict with
`AllowedClients`, publish the port on `127.0.0.1` only in Compose, treat commands as the local actor `iec104-master`
(Operator by default) in the audit trail, and disable commands with `Protocols:Iec104:CommandsEnabled=false` on any
network you do not fully control. Rejected clients, malformed frames, t0/t1 timeouts and every command are audited as
protocol/command events.
